* arc

[[http://www.gnu.org/licenses/gpl-3.0.txt][file:https://img.shields.io/badge/license-GPL_3-green.svg]]

arc (Artificial Reference Companion) is a local, offline, config-aware
oracle for Emacs. It answers Emacs, Elisp, Linux, NixOS and org-roam
questions grounded in this machine's actual configuration, using a
Retrieval Augmented Generation (RAG) approach, and cites the sources
you can jump to.

arc is a fork of [[http://github.com/s-kostyaev/elisa][ELISA]] by Sergey Kostyaev.

** No network at query time

arc reaches out to Ollama for embeddings and chat completion, and
nothing else. There is no web search, no remote document-conversion
service, and no other outbound request anywhere in the package.

** Data sources

arc indexes five kinds of source:

+ *file* :: local text files, parsed and chunked from disk.
+ *info* :: built-in and third-party Emacs info manuals.
+ *org-node* :: org-roam nodes.
+ *nix-option* :: NixOS module options.
+ *hm-option* :: Home Manager module options.

Every parse creates or updates a named collection. arc searches the
enabled collections, adds the relevant quotes to context, and lets the
LLM answer the query.

** Models

arc talks to a local [[https://ollama.com][Ollama]] instance and expects these models to be
pulled already:

+ ~qwen2.5-coder:3b~ or ~qwen2.5:7b~ for chat.
+ ~nomic-embed-text~ for embeddings.

** Installation

You need Emacs 29.2 or newer.

*** Vector search extension

arc stores embeddings in sqlite using the [[https://github.com/asg017/sqlite-vec][sqlite-vec]] ~vec0~ loadable
extension. Point arc at it with the ~ARC_VEC0_PATH~ environment
variable (set this before Emacs starts, e.g. by Nix):

#+begin_src sh
export ARC_VEC0_PATH=/path/to/vec0.so
#+end_src

If ~ARC_VEC0_PATH~ is unset or the file does not exist, arc warns
instead of failing to load, and the database will not have a working
vector table.

The file must actually be *named* ~vec0.so~ (or your platform's
equivalent, e.g. ~vec0.dylib~) -- SQLite's extension loader derives the
entry-point symbol it looks for from the file's own basename, so a
renamed or relocated copy at, say, ~/path/to/my-vec0.so~ is still a
perfectly valid extension file, still passes the ~file-exists-p~ check
above, and still fails to load -- obscurely, with no clear error
pointing at the filename as the cause.

** Known limitations

*** Asynchronous reindex never removes departed sources

~M-x arc-reindex-all~ (the interactive, non-blocking path -- see its
docstring) does not prune. A source that has genuinely left the corpus
(deleted, gitignored, newly excluded) keeps whatever content it was
last indexed with and stays citable indefinitely under this path
alone. This is deliberate, not an oversight: a long-running
asynchronous walk only ever knows "what this run has reached so far",
never "everything this collection currently has", and three separate
attempts to prune from the former each turned into a real, reproduced
way to delete sources the run had simply not gotten to yet.

Only a *synchronous* reindex prunes -- run one occasionally to actually
remove departed sources:

#+begin_src elisp
(arc-reindex-all)                  ; every collection in `arc-index-plan'
(arc-reindex-all '("dotfiles"))     ; just one collection
#+end_src

** Running the tests

#+begin_src sh
ARC_VEC0_PATH=/path/to/vec0.so ./test/run.sh
#+end_src

This runs every ERT suite under ~test/~ and exits non-zero if any
suite fails.
